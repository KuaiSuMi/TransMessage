# QQ 控制 Codex

更新时间：2026-10-29，Asia/Shanghai。TransMessage 0.3.0。

## 开始使用

1. 在「QQ 机器人」绑定自己的私聊目标。
2. 打开「QQ 控制」，选择本人、启用并保存连接。普通用户会话自动发现，无需逐个授权。
3. 「已有 Desktop」与「实时会话」显示在同一页，按各自能力操作。需要等待输入提醒和远程回答时，在该页选择项目目录创建实时会话。
4. 手机私聊机器人发送 `任务`，取得 `#会话编号`。群消息和其他用户不能执行控制操作。

## 引用回复与图文草稿

引用机器人发来的完成通知，直接回复要求，即可继续对应会话。引用待回答通知，直接发送答案，即可回答那一道问题。命令审批通知可引用后回复 `批准` 或 `拒绝`；不会把它当成新任务。

新消息携带的引用索引映射到会话和原问题；引用中的旧正文、旧图片不会再次发送给 Codex。索引按控制者隔离，DPAPI 加密保存 30 天、最多 2000 条。升级前的旧 QQ 消息没有索引，请改用 `#编号 要求`；过期或不明引用会明确报错。

图片和文字分开发送时使用草稿，不按静默时间猜测用户是否发完：

```text
引用一条机器人通知，回复 /d
发送图片
发送：请检查图中的错误
发送 /s
```

`/draft` 与 `/d` 相同，引用后均无需输入编号。先文字后图片时，第一条发送 `/d 文字要求`，再上传图片，最后 `/s`。引用会话直接发送图片也会自动开始草稿。只有一份草稿时，后续图文和 `/s` 无需编号；同时存在多份草稿时，每条消息需引用对应会话或带 `#编号`，不会猜测目标。

| 指令 | 行为 |
|---|---|
| `任务` | 列出可发现的 Desktop 和已创建的实时会话 |
| `状态 a1b2c3d4e5f6` | 查询会话；Desktop 实时状态显示未知 |
| `#a1b2c3d4e5f6 你的要求` | 向指定会话发送文字；也可引用通知直接回复 |
| `/d` 或 `/draft` | 开始或追加图文草稿，可附文字和图片 |
| `/s` | 将草稿作为同一轮输入发送，可附最后一段图文 |
| `/c` | 取消当前草稿 |
| `/model`、`/model 模型名` | 查询或修改实时会话下一轮模型 |
| `/reasoning`、`/reasoning high` | 查询或修改下一轮推理强度 |
| `继续 a1b2c3d4e5f6 要求` | 向指定会话发送文字 |
| `待回答` | 当前实时连接的有效问题 |
| `回答 A1B2C3D4 2` | 按问题码回答，数字对应选项，也支持自由文本 |
| `回答 A1B2C3D4 2 \| 额外说明` | 按顺序回答多个问题 |
| `批准 A1B2C3D4`、`拒绝 A1B2C3D4` | 处理完整显示的本次审批 |

斜杠指令可用 `#a1b2c3d4e5f6 /d` 或 `/d #a1b2c3d4e5f6` 指定目标。编号支持唯一的末 12 位或完整 UUID；引用和编号冲突时不发送。

每份草稿最多 8 张图片、6000 字符；图片支持 PNG、JPEG、GIF，每张最多 10 MiB。图片经过实际解码校验，下载失败不提交整条消息，也不丢弃已有草稿。图片缓存最多 512 MiB、保留 30 天，供 Desktop 稍后消费队列。草稿在内存中保存，闲置 30 分钟或断开控制连接后清除。实时会话忙碌时 `/s` 保留草稿，等待本轮结束后再提交；不会自动新增排队任务。待回答问题只接受文字。

## 统一入口，两种能力

**已有 Desktop · 共享队列**使用官方 `thread/read` 和 `thread/queue/add`。本地 helper 只负责读取和入队，不会对这些会话调用 `thread/resume` / `turn/start`。支持图文追加；Desktop 关闭或未消费时，入队不代表执行，空队列也不能证明完成。

当前 Windows Desktop 官方实时通道仍不可连接（socket 10050）。因此不能从 QQ 获取原窗口待输入状态、回答原窗口问题或修改其模型。`TransMessage.exe codex probe-desktop` 可重新诊断连接和发现会话，不提交提示。

**TransMessage 实时会话**由本程序管理的 Codex app-server 创建，使用 `workspace-write`、`on-request` 审批和用户审核。支持等待输入、远程回答、图片和下一轮模型设置。`/model` 的列表和 `/reasoning` 的档位来自当前 Codex；列表不代表账户一定有调用额度。模型设置只作用于指定会话的下一轮，不改变正在执行的轮次。

保持 TransMessage 在托盘运行。退出、停用或变更控制连接会结束托管进程、清除草稿和问题码；通知设置刷新不会重启连接。已产生历史的实时会话可重新连接继续；尚未启动第一轮的空会话可能没有持久记录。

本版不新增运行中引导、队列管理指令、当前会话切换器或多会话管理面板。多个会话原有的并行执行、独立通知和输入隔离仍保留。

## 问题、审批与消息边界

问题码绑定当前连接、会话、轮次和请求，15 分钟有效。连接断开、轮次结束或已处理后失效；引用旧问题不会启动新任务。提交答案后等待 Codex 确认；超时报告不确定，不自动重放。

敏感问题只能在电脑密码输入框回答。普通答案不写入 TransMessage 通知历史，但会进入对应 Codex 会话和模型请求。只有未脱敏、未截断、完整展示且无额外权限扩展的命令能「批准本次」；缺少完整差异的文件审批只能拒绝。没有永久批准或全部批准。

控制指令仅接受绑定本人的私聊，限最近 5 分钟、未来偏差不超过 1 分钟，每分钟最多 12 条，持久去重 7 天。无需逐会话授权不代表取消账户身份校验或 Codex 自身审批。

## 通知历史和时间

通知及控制回复带 `#会话编号` 和简短任务名。名称提取实际请求、去掉 Markdown 和多余空白，最多 32 个可见字符；配置中的名称和旧消息不被改写。

原始时间取来源事件，统一显示为北京时间、精确到秒，例如 `原始时间：2026-10-29 12:34:56（北京时间）`。来源未提供时间时标明接收时间；内部保留原始时区和小数秒。

Desktop 完成监听与 notify hook 共享去重，多个会话独立跟踪。启动恢复解析状态，但不补发启动前已完成的历史通知。通知历史保留最近 30 天、最多 500 条，脱敏后用当前 Windows 账户 DPAPI 加密；清空历史不清除去重，也不删除 QQ 消息。投递结果不确定时不会自动重发。
