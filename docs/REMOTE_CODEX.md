# QQ 控制 Codex

更新时间：2026-10-29，Asia/Shanghai。TransMessage 0.3.1。

## 开始使用

1. 在「QQ 机器人」绑定自己的私聊目标。
2. 打开「QQ 控制」，选择本人、启用并保存连接。普通用户会话自动发现，无需逐个授权。
3. 「已有 Desktop」与「实时会话」显示在同一页，按各自能力操作。需要等待输入提醒和远程回答时，在该页选择项目目录创建实时会话。
4. 手机私聊机器人发送 `任务`，取得 `#会话编号`。控制指令通过选定本人的私聊发送。

## 点击会话编号

QQ 消息中的 `#会话编号` 使用官方可点击标签。点一下会把 `#编号 ` 填入输入框，接着输入要求并发送；也可在输入框复制编号。标签外观由 QQ 客户端决定。

## 引用回复与图文草稿

引用机器人发来的完成通知，直接回复要求，即可继续对应会话。已有 Desktop 会话收到消息后会在后台唤醒，当前页面保持原样。引用待回答通知，直接发送答案，即可回答那一道问题。命令审批通知可引用后回复 `批准` 或 `拒绝`。

引用索引关联对应会话、轮次和问题；提交给 Codex 的是本次新发的文字和图片。索引按控制者隔离，DPAPI 加密保存 30 天、最多 2000 条。引用索引不可用时，使用 `#编号 要求` 继续会话。

图片和文字分开发送时，使用草稿把它们作为同一轮提交：

```text
引用一条机器人通知，回复 /d
发送图片
发送：请检查图中的错误
发送 /s
```

`/draft` 与 `/d` 相同，引用后均无需输入编号。先文字后图片时，第一条发送 `/d 文字要求`，再上传图片，最后 `/s`。引用会话直接发送图片也会自动开始草稿。只有一份草稿时，后续图文和 `/s` 无需编号；同时存在多份草稿时，每条消息引用对应会话或带 `#编号`。

## 读全文，取文件

引用某一轮的完成通知，发送 `/full` 阅读该轮完整回复。默认从第 1 页开始，每页最多 4 段文字；有后续内容时，消息尾部会给出 `/full 2` 等下一页指令。全文消息保留同一轮的引用关联，引用它即可继续翻页。

引用完成通知发送 `/file`，机器人会发送该轮回复里的附件。每页包含 1 条文件清单和最多 3 个附件；继续页使用 `/file 2`、`/file 3`。文件清单和附件消息也可以引用，始终对应原来那一轮。

附件取自该轮最终回复中以 Markdown 格式写出的本地文件链接和图片链接。目标文件需要仍保存在电脑上；网页链接可在原回复中打开。`/file` 的参数是页码，文件由回复中的链接确定。

单个附件最高 200 MB。一次获取使用该条 QQ 指令的 5 分钟回复窗口；超时后重新发送指令。附件上传独立执行，可以同时继续其他会话。

全文与文件清单带原始时间，统一使用北京时间、精确到秒。需要继续任务时，引用同一条通知直接输入要求；查看全文或取文件无需启动新一轮。

## 指令

| 指令 | 行为 |
|---|---|
| `任务` | 列出可发现的 Desktop 和已创建的实时会话 |
| `状态 a1b2c3d4e5f6` | 查询会话；Desktop 实时状态显示未知 |
| `#a1b2c3d4e5f6 你的要求` | 向指定会话发送文字；也可引用通知直接回复 |
| `/d` 或 `/draft` | 开始或追加图文草稿，可附文字和图片 |
| `/s` | 将草稿作为同一轮输入发送，可附最后一段图文 |
| `/c` | 取消当前草稿 |
| `/full`、`/full 2` | 引用完成通知，读取该轮全文的指定页；每页最多 4 段 |
| `/file`、`/file 2` | 引用完成通知，取回该轮附件的指定页；每页最多 3 个附件 |
| `/model`、`/model 模型名` | 查询或修改实时会话下一轮模型 |
| `/reasoning`、`/reasoning high` | 查询或修改下一轮推理强度 |
| `继续 a1b2c3d4e5f6 要求` | 向指定会话发送文字 |
| `待回答` | 当前实时连接的有效问题 |
| `回答 A1B2C3D4 2` | 按问题码回答，数字对应选项，也支持自由文本 |
| `回答 A1B2C3D4 2 \| 额外说明` | 按顺序回答多个问题 |
| `批准 A1B2C3D4`、`拒绝 A1B2C3D4` | 处理完整显示的本次审批 |

草稿和模型指令可用 `#a1b2c3d4e5f6 /d` 或 `/d #a1b2c3d4e5f6` 指定目标。编号支持唯一的末 12 位或完整 UUID。`/full` 和 `/file` 通过引用确定具体轮次，引用和编号应指向同一会话。

每份草稿最多 8 张图片、6000 字符；图片支持 PNG、JPEG、GIF，每张最多 10 MiB。图片经过实际解码校验，下载失败时保留已有草稿，重发该条消息即可。图片缓存最多 512 MiB、保留 30 天，供 Desktop 消费队列。草稿在内存中保存，闲置 30 分钟或断开控制连接后清除。实时会话忙碌时 `/s` 保留草稿，等本轮结束后再次提交。待回答问题接受文字答案。

## 统一入口，两种能力

**已有 Desktop · 共享队列**通过官方 `thread/queue/add` 接收图文，随后使用 `codex://threads/wake/<uuid>` 在后台唤醒原宿主处理，当前页面保持原样。保持 Codex Desktop 运行；工作仍在原会话执行，完成后由 TransMessage 通知。

Desktop 原窗口的待回答问题和模型设置在 Desktop 中处理。`TransMessage.exe codex probe-desktop` 可检查实时通道和会话发现。

**TransMessage 实时会话**由本程序管理的 Codex app-server 创建，使用 `workspace-write`、`on-request` 审批和用户审核。支持等待输入、远程回答、图片和下一轮模型设置。`/model` 的列表和 `/reasoning` 的档位来自当前 Codex，调用使用你的 Codex 账户权限与额度。设置从指定会话的下一轮生效。

保持 TransMessage 在托盘运行。退出、停用或变更控制连接会结束托管进程、清除草稿和问题码；通知设置刷新不会重启连接。已产生历史的实时会话可重新连接继续；尚未启动第一轮的空会话可能没有持久记录。

多个会话可以并行执行，各自保留独立的草稿、问题和完成通知。

## 问题、审批与消息边界

问题码绑定当前连接、会话、轮次和请求，15 分钟有效。连接断开、轮次结束或已处理后失效。提交答案后等待 Codex 确认；超时会提示查询任务状态。

敏感问题在电脑密码输入框回答。普通答案进入对应 Codex 会话和模型请求。完整显示的命令支持「批准本次」；涉及脱敏、截断、额外权限或文件差异的审批在电脑查看处理。

控制指令接受绑定本人的私聊，消息时间限最近 5 分钟、未来偏差最多 1 分钟，每分钟最多 12 条，持久去重 7 天。Codex 审批按当前会话设置执行。

## 通知历史和时间

通知及控制回复带 `#会话编号` 和简短任务名。名称提取实际请求、去掉 Markdown 和多余空白，最多 32 个可见字符。

原始时间取来源事件，统一显示为北京时间、精确到秒，例如 `原始时间：2026-10-29 12:34:56（北京时间）`。来源未提供时间时标明接收时间；内部保留原始时区和小数秒。

Desktop 完成监听与 notify hook 共享去重，多个会话独立跟踪。启动恢复解析状态，但不补发启动前已完成的历史通知。通知历史保留最近 30 天、最多 500 条，脱敏后用当前 Windows 账户 DPAPI 加密；清空历史不清除去重，也不删除 QQ 消息。投递结果不确定时不会自动重发。
